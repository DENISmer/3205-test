# url-checker

Сервис асинхронной проверки списка URL: бэкенд принимает список ссылок, в фоне проверяет каждую HEAD-запросом и отдаёт прогресс/результаты; фронтенд позволяет создавать такие задания и следить за ходом их выполнения.

## Стек

- **Бэкенд:** Node.js, TypeScript (strict), NestJS, in-memory хранилище
- **Фронтенд:** TypeScript (strict), React, Vite, Zustand, Pico CSS
- **Docker:** отдельные образы под api/web + docker-compose

## Структура проекта

```
.
api/     — бэкенд (NestJS)
web/     — фронтенд (Vite + React)
.env     — общие переменные окружения (порты, CORS)
docker-compose.yml
```

## Запуск локально

Требуется Node.js и Yarn.

```bash
cp .env.example .env    # если .env ещё нет
yarn
yarn dev
```

Другие команды из корня:

```bash
yarn lint      # линт api + web
yarn format    # форматирование api + web
```

## Запуск в Docker

Требуется Docker + Docker Compose, `.env` в корне (см. `.env.example`).

```bash
docker compose up --build
```

Поднимет два контейнера:

- `api` — Nest-приложение, внимательно слушает `API_PORT`
- `web` — nginx, отдаёт собранный фронтенд на `WEB_PORT` (по умолчанию 5173) и проксирует `/api/*` на контейнер `api`

Приложение доступно на `http://localhost:${WEB_PORT}`.

## API

Базовый префикс — `/api`.

### `POST /api/jobs`

Создаёт задание на проверку списка URL. Возвращает `jobId` немедленно, не дожидаясь проверки.

```json
// запрос
{ "urls": ["https://example.com", "https://another-site.com"] }

// ответ 201
{ "jobId": "b433b357-6d3e-1111-sf523-123213123" }
```

Валидация: `urls` — непустой массив (макс. 100), каждый элемент — валидный URL, без дублей. Некорректный запрос → `400`.

### `GET /api/jobs`

Список всех заданий с краткой статистикой.

```json
[
  {
    "id": "b433b357-6d3e-1111-sf523-123213123",
    "createdAt": "2026-07-28T14:32:00.000Z",
    "status": "completed",
    "totalUrls": 4,
    "successCount": 4,
    "errorCount": 0
  }
]
```

### `GET /api/jobs/:id`

Детали задания: то же, что в списке + результат по каждому URL. `404`, если `id` не найден.

```json
{
  "id": "b433b357-6d3e-1111-sf523-123213123",
  "createdAt": "2026-07-28T14:32:00.000Z",
  "status": "completed",
  "totalUrls": 2,
  "successCount": 1,
  "errorCount": 1,
  "urls": [
    {
      "url": "https://example.com",
      "status": "success",
      "httpStatus": 200,
      "startedAt": "2026-07-28T14:32:00.100Z",
      "finishedAt": "2026-07-28T14:32:03.400Z",
      "durationMs": 3300
    },
    {
      "url": "https://this-does-not-exist.test",
      "status": "error",
      "error": "getaddrinfo ENOTFOUND",
      "startedAt": "2026-07-28T14:32:00.100Z",
      "finishedAt": "2026-07-28T14:32:05.900Z",
      "durationMs": 5800
    }
  ]
}
```

### `DELETE /api/jobs/:id`

Отменяет задание — статус становится `cancelled`, ещё не начатые URL тоже помечаются `cancelled`, уже начатые доедут до конца. Повторная отмена уже завершённого задания → `409`. Несуществующий `id` → `404`.

### `DELETE /api/jobs`

Удаляет все задания из списка (сверх ТЗ, для удобства очистки истории). Незавершённые задания сначала останавливаются, затем всё хранилище очищается. `204 No Content`.

## Принятые решения и допущения

- **In-memory хранилище** — по ТЗ БД не требуется; `JobStorage` вынесен за интерфейс, чтобы позже подменить на реальную БД без изменения сервиса.
- **Лимит 5 параллельных HEAD на задание** — реализован самописным пулом воркеров (очередь URL + 5 асинхронных обработчиков), без очередей — ТЗ явно допускает in-memory-подход.
- **Отмена** — один `AbortController`, прерывает и HEAD-запрос, и случайную задержку перед сохранением результата — иначе отмена «зависала» бы до 10 секунд.
- **Случайная задержка 0–10 с** — намеренно применяется сохранения
- **Защита от гонки ответов** — при переключении активного задания стор игнорирует ответ, если к его приходу `activeJobId` уже успел смениться.
